Two parts, clearly identified

Green: your Local Assistant

Runs on your computer. Connects to your normal browser, reads selected Overleaf projects, and stores the research index, citations, embeddings, and Updates feed locally.

Blue: the Remote Backend

Handles Meld accounts, installation approval, and authenticated Foundry requests. It is intended to run as an HTTPS service; it does not keep a project-archive repository.

In local development, both backends run on your computer. The colors identify their roles, not their physical location. Foundry inference still uses the configured model service.

Get started

  1. Create a Meld account on the remote website using Google. Google sign-in must be configured by the service operator. Signing in while linking an installation does not silently create a new Meld account.
  2. Install the local companion. Your account page on the remote website shows a one-line command for Windows (PowerShell) or macOS (Terminal). It downloads the signed release, checks it, installs it for your user account without administrator rights, starts it whenever you sign in, and opens the green local app. Running it again repairs or updates the installation. The current packages are self-contained test distributions, not signed consumer installers.
  3. Add the Overleaf connector to your normal Chrome profile. The companion registers the native host; you still approve the extension installation in the browser. A private store release also requires tester access. While the store release is pending, use the source launcher's documented unpacked-extension setup.
  4. Link the installation. Open Account in the green local app and choose Link Google account. Open the approval page, check the device and verification code, and approve only the request you just initiated.
  5. Sign in to Overleaf in the normal browser. Use the Overleaf sign-in control in Account if necessary. Meld does not request your Overleaf password or extract your browser's cookie database.
  6. Select projects and explicitly consent to processing. Open About me and expand Select Overleaf projects. Review Privacy & controls, then enable monitoring for the projects you want in Feed. Choose Review on an Update to inspect its complete source evidence. Only process research you are authorized to send to these services.

Google authentication for Meld and the browser's Overleaf session are separate. Keep the local app and normal browser running for fresh Overleaf reads. You do not need to open the extension popup every day.

How research becomes an update

The first import establishes existing project knowledge. Later checks compare file content, not ZIP timestamps. Foundry decides whether changes add, revise, or remove knowledge, or do not warrant a new update. Embeddings help match changes to existing facts; local scoring does not replace the model's decision.

The model selects source line ranges and the server copies their exact text into citations. Invalid references or model failures do not overwrite the last successfully processed research. Citations make claims inspectable; they are not a guarantee that every model interpretation is correct.

Checks normally run every five minutes, with periodic content verification and a manual Check for changes action. Identical supported text makes no additional model calls, including after a restart. Formatting-only changes can require analysis without producing a new update.

Initial imports are labelled as imports, not research that happened today. Update timestamps indicate when Meld observed the evidence. Overleaf is the only private-data source; this release has no WorkIQ integration, other news feed, automatic colleague sharing, or alternative inference provider.

Your controls

  • Pause monitoring: stop processing one selected project without deleting its existing knowledge.
  • Pause auto-connect: stop the browser connector; the pause persists across browser restarts.
  • Disconnect account: stop local processing and request credential revocation. If the remote service is unavailable, revocation is queued and shown as pending.
  • Forget local research: remove the selected account's local index and update history for that project. Overleaf originals and manual ZIP copies are unchanged.
  • Account deletion: contact Markus Mobius. There is not yet a self-service remote account-deletion screen.

Removing the extension does not delete the companion's stored research. A model request already dispatched cannot be recalled. See the privacy notice for storage locations, manual deletion, backups, and protection limitations.

Development and Dummy mode

From the repository root, use the full-stack launcher with .NET 10, Node 24/npm, and PowerShell 7:

.\run-dev.ps1 -Mode Dummy
.\run-dev.ps1 -Mode Dummy -SkipBuild
.\run-dev.ps1 -Mode Live
.\run-dev.ps1 -Check

Dummy: an explicitly synthetic account and Overleaf source, but real configured Foundry chat and embeddings. It consumes model quota and does not use a real Overleaf profile. Use the test-account approval flow and explicit project consent.

Live: real Overleaf through the normal browser and real Google-based Meld account linking. Missing credentials are errors, not simulated production success.

Keep the launcher terminal open. Ctrl+C stops its owned processes. An occupied port is a conflict, not permission to terminate another application. Dummy data and logs persist under .local-test\Dummy.

The repository's README.md documents independent Foundry/Google configuration and release procedures; AGENTS.md records the project direction and instructions for future development. Never put tokens, Google secrets, or private Overleaf evidence into source control.

Current limitations and release status

  • Supported research text: UTF-8 .tex, .bib, .md, and .txt. PDFs and images are not analyzed. Current text limits are 128 KiB per file and 256 KiB per project.
  • Hosted www.overleaf.com, normal Chrome/Edge profiles, and one connected profile at a time. Safari, Firefox, self-hosted Overleaf, editing, and live collaboration are not supported.
  • The Windows package has been execution-tested. macOS packaging and registration code still need live Mac validation; signing/notarization and store approval remain separate release gates.
  • Real Google configuration, public HTTPS deployment, and live connector verification must be completed for a production rollout. A local demo or passing synthetic test does not establish those outcomes.
  • Indexed research is encrypted, but manual exports and temporary transfers are not all encrypted by Meld. Loopback transport is HTTP/WS. See the complete disclosure.
